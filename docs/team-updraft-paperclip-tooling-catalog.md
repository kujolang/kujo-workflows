# Team Updraft Paperclip Tooling Catalog

Date: 2026-07-07

Purpose: give Team Updraft a compact map of the Kujo ecosystem tools, what each tool does, and how each one can support agentic workflows in Paperclip.

## Category Key

| Category type | Meaning |
| --- | --- |
| Core | Language, runtime, package, or foundation layer used underneath other tools. |
| Primitive | Reusable building block for agent workflows, AI calls, orchestration, retrieval, or contracts. |
| Workflow tool | Focused CLI or local utility that creates, verifies, compresses, or packages work artifacts. |
| Governance and safety | Boundary, privacy, release, security, policy, or approval tooling. |
| Showcase app | Working application that proves a pattern we can copy into Paperclip or customer-facing products. |
| Operating knowledge | Agent skills, workflow kits, playbooks, or reusable agent definitions. |
| Product surface | Human-facing desktop, site, campaign, or command-center surface. |

## Tool Catalog

| Tool | Category type | What it is | Why it is useful for Team Updraft and Paperclip |
| --- | --- | --- | --- |
| Kujo | Core - language/runtime | Kujo is the local-first programming language and runtime for deterministic automation, agentic workflows, native capabilities, package workflows, doctor checks, docgen, AI helpers, and machine-readable CLI contracts. | Paperclip needs workflows that agents can run repeatedly without turning every task into hidden chat state. Kujo gives Team Updraft a scriptable runtime for local proof packets, reproducible commands, explicit capability boundaries, and agent-readable outputs. |
| Kennel | Core - package/dependency workflow | Kennel manages deterministic Kujo package installs, lockfiles, trust policy, source dependencies, and local package validation. | Paperclip agents will need dependency workflows that do not drift silently between machines or runs. Kennel gives us a path to repeatable tool installation, package validation, and eventually controlled package distribution for internal agent workspaces. |
| AI SDK | Primitive - provider abstraction | AI SDK provides normalized OpenAI-compatible chat and embedding contracts, provider presets, retries, streaming callbacks, governance budgets, redaction controls, and deterministic fixture mode. | Paperclip should not bake provider-specific glue into every agent or workflow. AI SDK gives Team Updraft a provider-gated layer that can support OpenAI, OpenRouter, DeepSeek, and custom endpoints while keeping tests offline and response shapes predictable. |
| Agents SDK | Primitive - agent runtime | Agents SDK provides reusable agent workflow primitives for runners, tools, approvals, handoffs, tracing, sessions, memory, retrieval, artifacts, and budgets on top of AI SDK. | This is the closest direct fit for building Paperclip's agent execution model. It gives us a local-first substrate for agent runs with explicit contracts, test fixtures, and composable primitives instead of one-off orchestration code. |
| Spec | Primitive - task contract | Spec turns human work requests into structured `.spec.yml` task contracts with goals, scope, acceptance criteria, eval requirements, risks, dependencies, and approval points. | Paperclip agents need work packets that can be assigned, reviewed, and verified without ambiguity. Spec can become the bridge from a Paperclip task to an agent-readable contract with acceptance criteria and human approval points baked in. |
| Eval | Primitive - deterministic verification | Eval runs deterministic checks for files, commands, HTTP behavior, JSON outputs, snapshots, policies, and workflow artifacts with reports and CI-friendly exit behavior. | Paperclip needs a way to decide whether agent work passed without relying on the agent's own summary. Eval gives Team Updraft repeatable acceptance gates for agent tasks, release workflows, generated artifacts, and regression checks. |
| Dispatch | Primitive - workflow orchestration | Dispatch is a resumable multi-step workflow engine with templates, retries, approval gates, persisted run state, traces, signed export/import bundles, and policy controls. | Paperclip can use Dispatch patterns for long-running, auditable agent processes that need stop points and approvals. It is useful for turning a Paperclip assignment into a traceable execution graph rather than a single opaque model call. |
| Watchdog | Primitive - AI telemetry and proxy | Watchdog is an OpenAI-compatible proxy, SQLite telemetry store, dashboard, and JSON API for model calls, tool calls, agent steps, audit events, cost, latency, and errors. | Paperclip will need observability for agent behavior, cost, latency, and failure patterns. Watchdog lets Team Updraft inspect agent traffic locally, export telemetry, and debug provider or workflow problems with structured evidence. |
| MCP | Primitive - agent tool gateway | MCP provides a Kujo framework for building Model Context Protocol servers with tools, resources, path guards, request limits, auth, and multi-root workspaces. | Paperclip agents need safe ways to access repo, filesystem, and service capabilities. MCP gives us a standard tool gateway pattern so agents can use powerful integrations behind explicit contracts and guardrails. |
| RAG | Primitive - grounded retrieval | RAG is a local retrieval starter kit for ingesting documents, chunking content, building offline or AI embeddings, hybrid search, citations, and query APIs. | Paperclip agents will need grounded context from docs, policies, repos, tasks, and customer material. RAG gives Team Updraft a local knowledge layer with namespace isolation and citations so agents can answer from evidence instead of memory alone. |
| RunLedger | Workflow tool - run receipts | RunLedger records local agent build runs with task, model/provider, prompt metadata, git anchoring, dirty state, changed files, manual usage/cost, verdicts, follow-ups, comparisons, and reports. | Paperclip needs durable receipts for what an agent did, what it changed, and what it cost. RunLedger gives Team Updraft a lightweight run history that can support audits, retrospectives, customer proof, and agent performance comparisons. |
| CaseFile | Workflow tool - incident evidence | CaseFile packages failed commands, imported logs, or manual incident notes into reproducible case bundles with provenance, redaction, reproduction notes, JSON, Markdown, and handoff files. | When an agent hits a failure, Paperclip should capture a useful evidence packet instead of losing the context in chat. CaseFile gives Team Updraft a standard failure handoff format for humans or follow-up agents to triage and fix. |
| Muzzle | Workflow tool - quiet execution | Muzzle runs known workflows quietly, writes full logs to disk, emits compact agent-facing summaries, tracks loop state, and redacts secrets. | Paperclip will run many tools behind agent workflows, and raw logs can drown the useful signal. | ShipCheck | Workflow tool - release readiness | ShipCheck scans repositories for release-readiness signals, generates Markdown or JSON reports, creates checklists, drafts release notes, and provides deterministic gate semantics. | Paperclip can use ShipCheck as a release confidence gate before merging, publishing, or handing work to a client. | Concord | Workflow tool - artifact drift | Concord detects drift between code, CLI behavior, docs, examples, specs, evals, schemas, metadata, and source-of-truth artifacts, then produces findings and task cards. | Agent-built systems often fail when docs, commands, and contracts diverge. Concord helps Paperclip catch mismatches early and turn drift into fix-ready work for agents or humans. |
| PatchBrief | Workflow tool - diff handoff | PatchBrief inspects git diffs and generates implementation briefs, test suggestions, and reviewer handoff notes without calling an AI provider. | Paperclip can use PatchBrief to make every agent diff reviewable by another agent or a human. | ChangeBucket | Workflow tool - change footprint | ChangeBucket measures the size, shape, and risk footprint of a code change by counting files, churn, categories, dependencies, lockfiles, generated files, CI files, deletions, and budget conformance. | Paperclip needs blast-radius checks before trusting agent-generated changes. ChangeBucket gives Team Updraft a fast read on whether a task stayed inside its expected scope and whether it should receive deeper review. |
| Scent | Workflow tool - context packaging | Scent creates deterministic task context packs with Markdown, JSON, manifests, selected files, metadata, redactions, token budgets, target-model presets, and changed-file selection. | Paperclip agents need the right amount of context, not the whole repo. | Scout | Workflow tool - repo intelligence | Scout turns a repository into an agent-readable context pack with file trees, language breakdowns, dependencies, routes, security smells, generated `llms.txt`, checklists, and structured indexes. | Paperclip can use Scout when onboarding a repo, assigning an agent, or preparing a review. | Lens | Workflow tool - browser QA evidence | Lens drives a real browser to inspect local URLs, capture screenshots, console and network data, blank-page and overflow findings, accessibility checks, link checks, visual baselines, flows, and Agent Repair Brief JSON. | Paperclip needs proof that frontend work actually renders and behaves. | Fence | Governance and safety - architecture boundaries | Fence is a deterministic architecture-boundary linter for imports, layers, and repo rules; it is not a permissions sandbox. | Paperclip agents need guardrails that prevent cross-layer sprawl and accidental architecture erosion. | Redact | Governance and safety - privacy/context sanitization | Redact is a deterministic anonymization pipeline that scans, sanitizes, verifies, and packs sensitive Markdown or text into model-ready context with local audit trails. | Paperclip workflows will ingest customer, team, and operational text that may contain secrets or private details. | Howl | Workflow tool - showcase artifacts | Howl renders deterministic showcase cards, Markdown, HTML, SVG, galleries, and captions from examples and manifests. | Paperclip will need to explain agent outcomes to clients and internal reviewers. | PackWrite | Workflow tool - agent pack compiler | PackWrite compiles a mega prompt and repository context into validated agent execution packs with phase files, handoffs, review checklists, and deterministic validation. | Paperclip will benefit from repeatable agent packs instead of improvising prompts per task. ## High-Value Paperclip Stacks

| Stack | Tools | Paperclip use |
| --- | --- | --- |
| Task-to-agent execution | Intake, Spec, Scent, Scout, Agents SDK, Dispatch | Turn inbound work into scoped, assignable, context-bounded agent runs with clear contracts and resumable state. |
| Verified fix loop | Spec, Scout, Scent, Lens, Eval, PatchBrief, ChangeBucket, RunLedger, CaseFile | Move a bug or feature from task definition through implementation, browser proof, deterministic verification, diff handoff, run receipt, and failure evidence. |
| Governance and review | Fence, Concord, ShipCheck, Redact, Watchdog, RunLedger | Keep agent work inside architecture boundaries, prevent sensitive context leakage, detect artifact drift, inspect AI telemetry, and gate releases. |
| Knowledge and customer context | RAG, Redact, Intake, SSG, CMS, Strata or TotalRecall integrations | Ingest and sanitize knowledge, ground agent answers in citations, and publish reviewed outputs or learnings. |
| Human control surface | Cinch, AI Chat, Watchdog, Lens, SiteKit, Kujo Command | Build a Paperclip operator experience that makes context, approvals, diffs, telemetry, proof, and agent roles visible. |

## Recommended Starting Point

For Paperclip's first internal agentic workflow, start with the narrow stack `Intake -> Spec -> Scent or Scout -> Agents SDK or Dispatch -> Eval -> RunLedger`, then add `Lens` for browser-facing work and `Watchdog` for model telemetry. That gives Team Updraft an end-to-end path from incoming work to verified, receipted agent output before adding broader release, drift, and product-surface layers.
